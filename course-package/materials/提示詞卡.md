### 練習：出席率算錯了（p-debug-lab）

- 時段：13:00–13:15｜用 AI 找錯與修正程式碼
- 說明：一般聊天：整段複製貼上

```text
我在課程清單看「消防安全講習」的出席率。
我預期看到：4 人報名、2 人簽到，應該是 50%。
實際看到：顯示 200%；沒人報名的課顯示 NaN%。
F12 Console 的錯誤訊息：沒有錯誤訊息
請先告訴我原因，再修正下面這個函式，只改必要的地方：

function attendanceText(courseId) {
  const total = query('SELECT COUNT(*) AS n FROM enrollments WHERE course_id = ?', [courseId])[0].n;
  const done = query('SELECT COUNT(*) AS n FROM enrollments WHERE course_id = ? AND checked_in_at IS NOT NULL', [courseId])[0].n;
  return Math.round(total / done * 100) + '%';
}
```

## 單元三：AI 工程實戰技巧與最佳實務

### 用 Codex 一次補上三個功能（p-codex-build）

- 時段：14:45–15:35｜【實作演練 2-A】依規格做出成品
- 說明：在 Codex 貼上；它會自己讀資料夾裡的檔案

```text
請先讀 AGENTS.md、docs/spec.md、docs/plan.md 和 signin.html。
這次只做 plan.md 的第二步：把 signin.html 預留的三個功能插槽寫好——
1. checkIn(enrollmentId)：簽到，已經簽到過要擋下來
2. attendanceText(courseId)：出席率 = 已簽到 ÷ 報名，沒人報名回傳「—」
3. exportCsv(courseId)：匯出簽到名單 CSV，開頭加 UTF-8 BOM
只改「功能插槽 1～3」開始與結束標記之間的程式；基本版其他地方、docs 裡的文件都不要動。
資料表欄位和 query、run、save、render、showMsg、nowText、downloadFile 這些函式，以 signin.html 現有的為準。
動手前先用三句話說你的理解，說完直接開始改，不用等我回覆。
做完告訴我：改了哪三個函式、我要怎麼在畫面上逐項驗收。
```

### Code Review 與弱點掃描（Codex）（p-review）

- 時段：15:55–16:20｜【實作演練 2-B】測試、除錯與 Code Review
- 說明：Codex：只讀不改

```text
請讀 AGENTS.md 和 signin.html，以資安審查者的角度做 Code Review。
這次只要讀、不要修改任何檔案，逐項回報：
1. SQL 注入：有沒有 SQL 是把使用者輸入直接接成字串？
2. XSS：姓名、單位、課程名稱顯示到畫面前，有沒有跳脫？
3. 規則檢查：額滿、重複報名、必填、重複簽到，有沒有在程式裡檢查，而不是只靠畫面？
4. 資料外洩：資料庫檔 signin.db 與匯出的 CSV，有沒有多存或多帶不需要的資料？
5. 邏輯錯誤：沒人報名、名額剛好滿、同名不同員編時，會不會算錯？
每一項寫：在哪個函式、什麼問題、風險高／中／低、建議怎麼修。
```
