# Code Review 與弱點掃描提示詞

> 實作演練 2-B 用，全班用同一份檢查項目，結果才能互相比較。
> 審查用 **Codex 版**（Codex 直接讀整個 `signin.html`，只讀不改，額度約 1%）；Codex 額度用完才用 **聊天版備案**（把整份程式貼給一般聊天——會變成附件，免費方案一天只有幾次，只做一次）。兩版檢查的五項一樣。
> 重點：先請 AI 列問題、不要改程式，由你決定要修哪一項。

## 提示詞 1A：審查（Codex 版，只讀不改）

事前準備：`AI實作` 資料夾裡要有 `signin.html` 和 `AGENTS.md`；左上角「ChatGPT ⌄」選單切到 Codex、「選擇專案」→「新專案」加入 `AI實作` 資料夾、開新對話。

```text
請讀 AGENTS.md 和 signin.html，以資安審查者的角度做 Code Review。
這次只要讀、不要修改任何檔案，逐項回報：
1. SQL 注入：有沒有 SQL 是把使用者輸入直接接成字串？
2. XSS：姓名、單位、課程名稱顯示到畫面前，有沒有跳脫？
3. 規則檢查：額滿、重複報名、必填、重複簽到，有沒有在程式裡檢查，而不是只靠畫面？
4. 資料外洩：瀏覽器儲存與匯出的 CSV，有沒有多存或多帶不需要的資料？
5. 邏輯錯誤：沒人報名、名額剛好滿、同名不同員編時，會不會算錯？
每一項寫：在哪個函式、什麼問題、風險高／中／低、建議怎麼修。
```

## 提示詞 1B：審查（聊天版備案）

事前準備：

1. 在瀏覽器打開 `AI實作/signin.html`，按 `Ctrl + U`（Mac：`Cmd + Option + U`）打開原始碼。
2. 按 `Ctrl + A` 全選、`Ctrl + C` 複製（Mac：`Cmd + A`、`Cmd + C`）。
3. 開一個新的一般聊天，貼上下面的提示詞，再把程式貼在最後一行下面，送出。

```text
下面是一個網頁檔 signin.html 的完整程式（教育訓練報名簽到表，資料庫是瀏覽器裡的 SQLite）。
請以資安審查者的角度做 Code Review。這次只要找問題、不要改寫程式，逐項回報：
1. SQL 注入：有沒有 SQL 是把使用者輸入直接接成字串？
2. XSS：姓名、單位、課程名稱顯示到畫面前，有沒有跳脫？
3. 規則檢查：額滿、重複報名、必填、重複簽到，有沒有在程式裡檢查，而不是只靠畫面？
4. 資料外洩：瀏覽器儲存與匯出的 CSV，有沒有多存或多帶不需要的資料？
5. 邏輯錯誤：沒人報名、名額剛好滿、同名不同員編時，會不會算錯？
每一項寫：在哪個函式、什麼問題、風險高／中／低、建議怎麼修。

（在這一行下面貼上 signin.html 的完整程式）
```

## 提示詞 2：修正一項（在 Codex）

回到做功能的那個 Codex 對話貼上（Code Review 若是在聊天做的，就把那一項複製過來）：

```text
請修正 Code Review 的這一項：[貼上 Review 裡那一項]。
只改那個函式，其他地方不要動。
改完告訴我改了哪裡、要重測驗收清單的哪一項。
```

改完在瀏覽器按 F5，重測那一項。Codex 額度已經用完：把要修的那一項記下來，額度恢復後再用同一段提示詞請 Codex 修。

問題若在三個函式以外（基本版本身），記下來交給講師。

## 這五項在查什麼（白話）

| 項目 | 一句話 | 正確的做法 |
|---|---|---|
| SQL 注入 | 使用者打的字被當成資料庫指令執行 | SQL 裡只放 `?`，輸入用參數傳進去 |
| XSS | 使用者打的字被當成網頁程式執行 | 顯示前跳脫 HTML，或用 `textContent` |
| 規則檢查 | 畫面上的檢查可以被繞過 | 程式裡再檢查一次名額、重複、必填 |
| 資料外洩 | 存了或匯出了不該給的資料 | 只存規格書列的欄位，不存身分證字號、病歷號 |
| 邏輯錯誤 | 平常沒事，邊界情況出錯 | 沒人報名顯示「—」、剛好額滿時擋下第一個超額的人 |

## 看審查結果時要注意

- AI 可能會把「建議」講得很嚴重，對照規格書判斷：規格書說「這次不做」的（例如登入），不算這次的缺陷。
- 風險等級是 AI 的判斷，你可以依實際情況調整。
- 修完一定要重跑相關的驗收項目，確認沒有改壞其他功能。
