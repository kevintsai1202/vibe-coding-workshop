# 規格書：教育訓練報名簽到表

> 參考答案。實作演練 1 做不完或內容差太多時，把本檔改名成 `spec.md` 放進 `AI實作/docs/` 接續實作演練 2。
> 晴川醫院與人物皆為虛構。

## 1. 專案目標

- 要解決的問題：教學研究部每月辦約 5 場院內教育訓練，報名靠 LINE 與紙本、簽到靠紙本簽名單，會後要人工對回 Excel 算出席率，每場整理 2～3 小時；還常發生額滿後仍有人報名、同一人被重複報名。
- 做完之後：開課、報名、簽到、出席率、匯出都在同一個網頁完成，額滿與重複報名由系統擋下。
- 成功的樣子：上課當天在門口用筆電點「簽到」，下課就能看到出席率並匯出簽到名單，整理時間降到 10 分鐘內。

## 2. 使用者與使用情境

| 使用者 | 什麼時候用 | 要做什麼 |
|---|---|---|
| 王小芸（教學研究部行政專員） | 開課前 | 新增課程、依各單位回報幫同仁報名 |
| 王小芸 | 上課當天 | 在教室門口開著名單，同仁報員工編號後按「簽到」 |
| 王小芸 | 會後、月底 | 看出席率、匯出簽到名單給張主任與各單位 |
| 張主任（教學研究部主任） | 月底 | 看每堂課出席率（由小芸匯出給他） |

只有小芸一人在教學研究部的電腦上使用，不需要登入。

## 3. 功能清單與驗收條件

| 編號 | 功能 | 驗收條件 |
|---|---|---|
| F1 | 身為行政專員，我想要新增課程，這樣才能開放報名 | 填完名稱、日期、時間、地點、名額、時數按「新增課程」→ 課程清單立刻出現這堂課，顯示 0 / 名額 |
| F2 | 身為行政專員，我想要在課程清單看到每堂課的報名人數與出席率，這樣不用自己算 | 打開頁面 → 消防安全講習顯示「4 / 40 人」、出席率「50%」 |
| F3 | 身為行政專員，我想要幫同仁報名，這樣名單都在同一個地方 | 在某堂課輸入員工編號、姓名、選單位按「報名」→ 名單多一列，報名人數加 1 |
| F4 | 身為行政專員，我想要看某堂課的報名名單，這樣能回答單位窗口的問題 | 在課程清單按「查看名單」→ 下方顯示該課程所有報名者與簽到狀態 |
| F5 | 身為行政專員，我想要在上課當天按一下就完成簽到，這樣不用再對紙本 | 在名單某一列按「簽到」→ 該列顯示簽到時間，按鈕消失 |
| F6 | 身為主任，我想要看到出席率，這樣知道哪些課缺席多 | 消防安全講習幫林志明簽到後 → 出席率由 50% 變成 75% |
| F7 | 身為行政專員，我想要匯出簽到名單，這樣能回報主任與各單位 | 按「匯出 CSV」→ 下載檔案，用 Excel 打開中文正常，含簽到時間 |
| F8 | 身為行政專員，我想要資料自動保存，這樣關掉瀏覽器也不會不見 | 新增資料後重新整理頁面 → 資料都還在 |
| F9 | 身為學員，我想要一打開就有示範資料，這樣可以馬上測試 | 第一次打開 → 看到兩堂課與六筆報名（見第 6 節示範資料） |

## 4. 業務規則

| 編號 | 規則 | 違反時畫面顯示 |
|---|---|---|
| R1 | 報名人數達到名額時不能再報名 | 「名額已滿，無法報名」，名單與人數不變 |
| R2 | 同一員工編號在同一堂課只能報名一次（報不同課程沒問題） | 「E1001 已報名過這堂課」，名單不變 |
| R3 | 報名時員工編號、姓名、單位都必填；員工編號為 E 加 4 碼數字 | 「請填寫員工編號、姓名、單位」或「員工編號格式為 E 加 4 碼數字，例如 E1001」 |
| R4 | 每人每堂課只能簽到一次，簽到後記下時間 | 已簽到者顯示簽到時間，不再顯示「簽到」按鈕 |
| R5 | 出席率 = 已簽到人數 ÷ 報名人數，四捨五入到整數百分比 | 沒人報名時顯示「—」 |
| R6 | 匯出 CSV 開頭加 UTF-8 BOM | Excel 打開中文不亂碼 |
| R7 | 每次資料變更後自動保存 | 重新整理或關掉再開，資料還在 |
| R8 | 新增課程時所有欄位必填；名額為 1 以上的整數；時數大於 0 | 「請填寫完整的課程資料」或「名額至少 1 人」 |

單位只能從固定清單選：護理部、醫務部、藥劑部、檢驗科、放射科、總務室、人資室、資訊室、教學研究部、社工室。

## 6. 資料表設計（SQLite）

SQLite 是一種不用安裝伺服器的輕量級資料庫。課程資訊只存在 `courses`，報名只記「報哪一堂課」，同一件事只存一次。

### courses（課程）

| 欄位 | 型別 | 說明 | 範例 |
|---|---|---|---|
| id | INTEGER 主鍵，自動遞增 | 課程編號（主鍵：每一列的唯一編號） | 1 |
| title | TEXT，必填 | 課程名稱 | 消防安全講習 |
| date | TEXT，必填 | 上課日期，格式 YYYY-MM-DD | 2026-11-05 |
| start_time | TEXT，必填 | 開始時間，格式 HH:MM | 14:00 |
| location | TEXT，必填 | 地點 | 第一會議室 |
| capacity | INTEGER，必填 | 名額，1 以上 | 40 |
| hours | REAL，必填 | 時數，大於 0 | 2 |

### enrollments（報名）

| 欄位 | 型別 | 說明 | 範例 |
|---|---|---|---|
| id | INTEGER 主鍵，自動遞增 | 報名編號 | 1 |
| course_id | INTEGER，必填 | 報的是哪一堂課，對應 courses.id（關聯：指向另一張表的編號） | 1 |
| emp_no | TEXT，必填 | 員工編號，E 加 4 碼 | E1001 |
| name | TEXT，必填 | 姓名 | 陳美玲 |
| dept | TEXT，必填 | 單位（固定清單） | 護理部 |
| enrolled_at | TEXT，必填 | 報名時間，格式 YYYY-MM-DD HH:MM | 2026-10-19 10:15 |
| checked_in_at | TEXT，可空白 | 簽到時間；空白表示還沒簽到 | 2026-11-05 13:52 |

`course_id` 加 `emp_no` 設為不可重複（UNIQUE），資料庫本身也會擋下重複報名。

```sql
CREATE TABLE IF NOT EXISTS courses (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  date TEXT NOT NULL,
  start_time TEXT NOT NULL,
  location TEXT NOT NULL,
  capacity INTEGER NOT NULL CHECK (capacity >= 1),
  hours REAL NOT NULL CHECK (hours > 0)
);
CREATE TABLE IF NOT EXISTS enrollments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  course_id INTEGER NOT NULL REFERENCES courses(id),
  emp_no TEXT NOT NULL,
  name TEXT NOT NULL,
  dept TEXT NOT NULL,
  enrolled_at TEXT NOT NULL,
  checked_in_at TEXT,
  UNIQUE (course_id, emp_no)
);
```

## 7. API 文件（給之後的正式系統參考，這次不實作）

> 這次的成品是單一網頁檔，畫面與規則都在瀏覽器裡。若之後要讓各單位窗口自己上網報名，就要把規則搬到伺服器（後端），前端透過以下 API（前端與後端說好的溝通方式）傳資料。

| 方法 | 網址 | 做什麼 | 成功 | 失敗 |
|---|---|---|---|---|
| GET | `/api/courses` | 取得課程清單，含報名人數與簽到人數 | 200 | — |
| POST | `/api/courses` | 新增課程 | 201 | 400 欄位沒填或格式錯 |
| GET | `/api/courses/{id}/enrollments` | 取得某堂課的報名名單 | 200 | 404 課程不存在 |
| POST | `/api/courses/{id}/enrollments` | 幫某堂課報名 | 201 | 400 欄位沒填或格式錯；404 課程不存在；409 名額已滿或已報名過 |
| POST | `/api/enrollments/{id}/check-in` | 簽到 | 200 | 404 報名不存在；409 已簽到過 |
| GET | `/api/courses/{id}/attendance.csv` | 下載某堂課的簽到名單 CSV | 200 | 404 課程不存在 |

狀態碼白話：200 成功、201 新增成功、400 資料沒填好、404 找不到、409 跟現有資料衝突。

### 範例：報名 `POST /api/courses/2/enrollments`

請求：

```json
{ "emp_no": "E1006", "name": "蔡佳蓉", "dept": "檢驗科" }
```

成功回應（201）：

```json
{ "id": 7, "course_id": 2, "emp_no": "E1006", "name": "蔡佳蓉", "dept": "檢驗科",
  "enrolled_at": "2026-10-19 14:30", "checked_in_at": null }
```

名額已滿（409）：

```json
{ "error": "COURSE_FULL", "message": "名額已滿，無法報名" }
```

已報名過（409）：

```json
{ "error": "ALREADY_ENROLLED", "message": "E1006 已報名過這堂課" }
```

## 8. 技術架構與這次不做的事

### 技術架構

- 成品是一個網頁檔 `signin.html`，CSS 與 JavaScript 都寫在裡面，雙擊就能用瀏覽器打開
- 資料庫：sql.js 1.13.0（在瀏覽器裡執行的 SQLite），從 cdnjs 載入，需要網路
- 資料保存：每次資料變更後，把整個資料庫存到瀏覽器的 localStorage（瀏覽器內建的儲存空間），打開時先讀回來
- 匯出：CSV 檔開頭加 UTF-8 BOM（讓 Excel 知道是 UTF-8 的標記），Excel 打開中文不亂碼
- 匯出欄位：課程名稱、上課日期、員工編號、姓名、單位、簽到狀態（已簽到／未簽到）、簽到時間
- 開發方式：以講師準備的 `signin_基本版.html` 為起點（第一步已完成），第二步的三個功能寫在預留的功能插槽：
  - 插槽 1 `checkIn(enrollmentId)`：簽到（R4）
  - 插槽 2 `attendanceText(courseId)`：出席率文字（R5）
  - 插槽 3 `exportCsv(courseId)`：匯出簽到名單（R6）

### 這次不做

- 登入與帳號權限
- 取消報名、刪除或修改課程
- Email、LINE 通知
- QR Code 掃碼簽到
- 串接人資系統
- 多台電腦共用同一份資料

### 之後可以再做

- 取消報名與修改課程
- 各單位窗口自己上網報名（需要伺服器、登入與權限，照第 7 節 API 文件開發）
- QR Code 掃碼簽到
- 每位同仁的年度教育訓練時數統計
